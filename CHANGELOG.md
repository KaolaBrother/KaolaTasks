# Changelog

## Unreleased

- `@kaola/server` (#4 Agent API keys): tables `agent_keys` (`id`, `user_id`, `key_hash` NOT NULL UNIQUE, `label` NOT NULL DEFAULT '', `last_used_at` INTEGER NULL) via `CREATE TABLE IF NOT EXISTS` in `createDb`. Session HTTP: `POST /api/v1/agent-keys` body `{ "label"?: string }` → `201` `{ id, label, token, last_used_at: null }` (`token` only here; plaintext `ktk_` + 64 hex); `GET /api/v1/agent-keys` → `200` `{ keys: [{ id, label, last_used_at }] }` (no `token`, no `key_hash`); `DELETE /api/v1/agent-keys/:id` → `200` `{ ok: true }`; missing/not-owned → `404` `{ error: 'not_found' }`. Generate/list/revoke require `status === 'active'` (approved GitHub `claim_only` may manage own keys). Pending `POST` → `403` `{ error: 'forbidden', message: '你的账号待正式成员批准后方可生成 Agent Key。' }`; pending `GET`/`DELETE` → `403` `{ error: 'forbidden' }`. Unauthenticated session routes use the same oracle as `GET /api/v1/me` (`401` `{ error: 'unauthorized' }` or `302` `/login`). Bearer `GET /api/v1/agent/whoami` (child Fastify `onRequest`; `Authorization` scheme case-insensitive `Bearer`) → `200` `{ id, key_id, label, status, permission_level }` (`id` = user id); `401` `{ error: 'unauthorized' }` with `WWW-Authenticate: Bearer`. `key_hash` is sha256 hex of plaintext (`utf8`). `last_used_at` is unix seconds and ticks only on successful Bearer auth. No `@fastify/bearer-auth`; `node:crypto` only (no new npm dependency). Does not accept Bearer on `GET /api/v1/me`.
- `@kaola/server` (#5 token vault / credential profiles): tables `credential_profiles` (`id`, `forge`, `base_url`, `repo_full_name`, `token_encrypted`, `scopes_checked` TEXT NOT NULL DEFAULT `'[]'`, `created_by`; UNIQUE `(forge, base_url, repo_full_name)`) and `events` (`id`, `type`, `actor_user_id`, `created_at`, `details`) via `CREATE TABLE IF NOT EXISTS`. AES-256-GCM (`aes-256-gcm`, `{ authTagLength: 16 }`, 12-byte IV) layout `iv||ciphertext||tag` stored as base64 TEXT. Env `VAULT_MASTER_KEY` 64 hex chars required at `encryptToken`/`decryptToken`, not at `buildApp()` boot. Session HTTP (gate `status === 'active'` AND `permission_level === 'full'`): `GET /api/v1/credential-profiles` → `200` `{ profiles: [{ id, forge, base_url, repo_full_name, scopes_checked, created_by }] }` (never token / `token_encrypted`); `POST /api/v1/credential-profiles` body `{ forge, base_url, repo_full_name, token }` → `201` same shape as a list item (`scopes_checked` starts `[]`; does not call `validateToken`); duplicate unique triple → `409` `{ error: 'conflict' }`; invalid body → `400` `{ error: 'invalid_body' }`; missing/invalid vault key → `500` `{ error: 'vault_unconfigured' }`; `DELETE /api/v1/credential-profiles/:id` → `200` `{ ok: true, message: '请同时到 forge 侧撤销该 token。' }`; missing → `404` `{ error: 'not_found' }`; `claim_only` or pending → `403` `{ error: 'forbidden' }`. `forge` enum `github` | `gitlab` | `gitea`. Audit: create/delete write `events.type` `变更` with `details` `{"action":"create"|"delete","profile_id":<n>}`; module export `revealCredentialProfile(db, { profileId, actorUserId, agentKeyId })` returns plaintext and writes `type` `token 揭示` with `details` `{"agent_key_id":<n>,"profile_id":<n>}`. No HTTP that returns a forge token. After delete, reveal throws. `GET /` still `考拉任务服务占位`. MCP, task CRUD, claim, and `tasks` table still unimplemented. Server still does not import `@kaola/forge-adapters`.
